# 앱으로 내보내기: 클립보드 복원 경합

## 확인된 원인

기준 커밋: `58bc81b166a0cb74485a85893335515a610299f8`.

`TextInserter.insert`는 정리된 문자열을 NSPasteboard에 정상 기록한 뒤 ⌘V를 게시했지만,
수신 여부와 무관하게 별도 Task에서 1초 후 원래 클립보드를 복원했다.
대상 앱이 1초보다 늦게 읽으면 정리된 결과 대신 이전 클립보드를 받는다.
`changeCount` 검사는 외부 쓰기에 대한 보호일 뿐 수신 완료 확인이 아니었다.
또한 `TargetApp.send`는 Return이 꺼져 있으면 게시 후 200ms만 기다리고 원래 앱으로 돌아갔다.
이 경로에도 수신 완료 대기가 없었다.

## RED / GREEN 증거

시스템 클립보드를 건드리지 않는 고유 이름의 **실제 NSPasteboard**에서 프로덕션 삽입 함수를 호출했다.
수신 앱 경계만 주입하여 20ms / 1,150ms 읽기를 50회 교차 실행했다.
전체 문자열(한글·이모지·줄바꿈)을 비교했고, 각 게시·읽기 경계에 값·changeCount·경과 시간을 기록했다.
실제 앱 GUI·음성 인식·실제 LLM 서버의 종단 간 시험은 아니다.

| 버전 | 빠른 읽기 25회 | 지연 읽기 25회 | 전체 |
|---|---:|---:|---:|
| RED: 기존 1초 복원 | 25 성공 | 25 실패 | 25/50 성공 |
| GREEN: 수신 후 복원 | 25 성공 | 25 성공 | 50/50 성공 |

RED 대표 기록:

```text
cycle=19 post value="정리된 전체 문장 19 ✅\n마지막 줄" changeCount=2
cycle=19 read value="이전 원본 어 음 19" changeCount=3
```

GREEN에서는 같은 지연 읽기가 `changeCount=2`인 동안 전체 정리 문장을 받는다.
수신 확인 후 함수가 반환하면 원래 클립보드가 복원되어 있음을 매 회 추가로 검증한다.
RED 실행은 57.077초, 실패 25건으로 종료했다.
기존 테스트는 182개가 통과했으나 500ms 이내 읽기만 검증하여 이 문제를 잡지 못했다.

## 수정

- 고정 복원 타이머와 `pendingRestore`를 제거했다.
- 앱 활성화부터 게시·수신 확인·복원까지 직렬화하여 await 재진입 시 다음 쓰기가 앞선 값을 덮지 못하게 했다.
- 쓰기 성공 여부, 전체 문자열 readback, 소유권 changeCount를 게시 전에 확인한다.
- 게시 전에 고정한 AX 입력 요소에서 **전체 문자열이 새로 나타났을 때**만 수신으로 판단한다.
  예전처럼 끝 20글자가 같다는 이유로 성공 처리하지 않는다.
- 앱 PID와 입력 요소 포커스를 다시 확인한다. 확인 전에는 Return과 원래 앱 복귀를 하지 않는다.
- 수신 확인 후 원래 클립보드의 모든 읽을 수 있는 표현을 복원한다. 외부 소유자가 바꾼 클립보드는 덮어쓰지 않는다.
- 게시 후 미확인·취소·포커스 손실이면 타이머 복원 및 자동 재전송을 하지 않는다. 재전송은 중복 입력을 만들 수 있다.
- 원래 앱으로의 복귀는 수신 확인 뒤에 한다. Return 후 기존 200ms 완충은 유지한다.
  이 완충은 앱의 메시지 전송 완료를 증명하지 않는다.

`Coordinator.finishAndInsert`는 이미 `await refineOrFallback` / 오디오 다듬기 완료 후의
`outcome.text`를 전달한다. 이번 재현에서는 게시 직후 문자열 자체가 정확했으므로
다듬기 완료 대기 및 타임아웃 시 원문 폴백 정책은 변경하지 않았다.

## 검증 및 제한

```sh
swift test --filter ExportRaceReproductionTests
swift test
./Scripts/bundle.sh
git diff --check
```

회귀 범위: 50회 빠른/지연 읽기, 바이너리 포함 원본 복원, 외부 클립보드 변경,
게시/활성화 실패, 동시 호출, 부분/오래된 값 배제, Return 순서, 포커스 손실, 취소.

AX 값을 노출하지 않거나 문장을 변형하는 앱, 동일 문장을 같은 선택 영역에 다시 넣는 경우에는
완료를 보수적으로 미확인 처리할 수 있다. 3초 상한 후 새 텍스트를 클립보드에 유지하고
입력창/클립보드를 확인하라는 알림을 표시하며 원래 앱으로 강제 복귀하지 않는다.
이 경우 원래 클립보드는 자동 복원되지 않는다. 읽기 완료를 알 수 없는 상태에서 복원하면
확인된 경합이 다시 생기므로, 임의의 긴 타이머로 성공을 추정하지 않는다.

외부 프로세스와의 changeCount 검사·쓰기에는 OS 수준 원자적 비교 교환이 없으므로
프로세스 간 완전한 잠금은 보장하지 않는다. 실제 대상 앱의 Return 소비/전송 완료 확인은
기존 기능의 제한으로 남아 있다.

최종 검증 결과: `swift test` **190개 통과**(31.431초), `./Scripts/bundle.sh` 빌드·서명 성공,
`git diff --check` 통과. 원본 실행 로그는 이 작업 트리의 `build/diagnostics/{red,green,bundle}.log`에 보관한다.
