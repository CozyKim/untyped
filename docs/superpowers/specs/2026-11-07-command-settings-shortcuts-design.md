# Command settings and recording shortcuts

User decisions: configure speech that means edit vs submit vs ordinary dictation; add dedicated editing/literal recording shortcuts; support modifier combinations; do not add a submit shortcut (Enter already serves that purpose). Preserve working contextual partial edits and current `.worktrees/voice-edit-and-submit`.

Voice settings: master switch determines whether the primary/target recording keys distinguish commands. Separate edit/submit toggles and lists of exact trigger phrases (defaults 수정 / 보내). Edit phrases match the start of an utterance with a word boundary; submit phrases match the entire utterance. Everything else is ordinary dictation. Reject empty active lists and identical active edit/submit phrases. Dedicated edit recording ignores the prefix requirement; dedicated literal recording treats command words as body text. Literal means no command routing; the existing transcription/refinement backend still determines text cleanup.

Shortcuts: retain the primary and target-app recording keys, add optional edit and literal recording keys for the current input field, default unset. Each supports an existing standalone modifier or a modifier+key chord. Preserve legacy config string encoding for standalone modifiers, encode chords as structured objects. Use an active event tap to consume matched chord key events so they do not type into the target app; match exact modifiers, ignore repeats/self-generated events, and finish a held chord if its modifiers are released first. Prevent duplicate bindings and eager standalone-modifier/chord overlaps with a clear validation error. No submit key binding.

Recording state tracks the initiating route separately from insertion destination; only its initiating key ends it. Snapshot command settings and recording mode at start so saving settings mid-recording cannot reinterpret speech. Settings save updates inactive monitors; defer changing bindings for a current session until it completes to retain its release event. Dedicated edit never falls back to dictation or submission. Literal recording does not automatically Return, so command-like literal words can be reviewed.

Approaches: numeric shortcut text is opaque and hard to validate; fixed standalone modifiers alone fail the user's chord requirement. Use reusable UI controls for modifier or chord selection, a checked modifier set and key picker; no new dependencies or permission category. Command rules and chord matching are pure testable modules, with Coordinator responsible for integration.

Verify config migration, phrase boundaries/overlap, chord press/repeat/release/consumption, binding conflicts, literal/edit routing, settings changes during a session and regression suite. Build/sign/relaunch the worktree app, retaining the main checkout clean. Actual macOS global event-tap operation needs a live shortcut check; tests prove pure matching/state/serialization and existing text mutation safety.

Follow-up: modifier-only chords (Shift + right Command, etc.) are supported by physical side sets; see plans/2026-11-07-modifier-only-chords.md. They may coexist with contained standalone bindings via explicit strict-superset recording promotion. Ordinary-key chord overlap validation is unchanged.
